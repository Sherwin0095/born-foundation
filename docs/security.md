# BORN FOUNDATION — Security, Privacy & Child Safeguarding Architecture

## 1. Threat Model & Protections Applied
- **Unauthorised Media Exposure:** Private source archives and previews stay inside `.private/` (listed in `.gitignore`), outside `public/`. Only explicitly cleared non-identifying derivatives exist in `public/images/gallery/`.
- **Metadata / GPS Leakage:** Every image generated by `scripts/process-media.mjs` strips EXIF, XMP, IPTC, and ICC/GPS metadata prior to placement in `public/images/gallery/`.
- **Protected Admin Endpoints:** `GET /api/admin/media-inventory` enforces auth check (`401 Unauthorized` without valid staff context) and never reveals source filenames or minor photographs.
- **HTTP Security Headers (`next.config.ts`):**
  - `Content-Security-Policy` restricting script/style/img/connect/frame origins and `frame-ancestors 'none'`
  - `X-Frame-Options: DENY`
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=()`
  - `poweredByHeader: false`
- **Form & API Hardening:**
  - Server-side Zod schema trimming, length bounds, and anti-spam honeypot rejection
  - Same-origin header verification (`403` on cross-site browser POSTs)
  - Sliding-window per-IP rate limiting (`429 Too Many Requests` + `Retry-After`)
  - PII log masking (`maskEmail`) prevents plaintext personal addresses from writing to server logs
- **Database Least Privilege (`supabase/migrations/...sql`):**
  - Row Level Security enabled across all 12+ tables (`public` SELECT restricted to `status = 'published'`, `is_verified = true`, or `is_public = true AND approval_status = 'approved'`)
  - Role escalation prevented via `get_auth_role()` server-side function (`SECURITY DEFINER`)

## 2. Known Offline-Mode Boundaries (Blocked Pending Production Environment)
- In local `NEXT_PUBLIC_OFFLINE_MODE=true` mode, `/login` uses browser `localStorage` sandbox role sessions rather than cryptographically verified HTTP-only Supabase JWT cookies. Before public production launch, live Supabase Auth **MUST** be enabled (`NEXT_PUBLIC_OFFLINE_MODE=false`) so Next.js middleware/server components enforce server-side session verification on `/admin/**`.
- In-memory API rate limiting in `src/lib/security.ts` operates per Node process; multi-replica serverless deployments should bind Redis/Upstash rate limiting.
- Live financial gateway credentials (Razorpay/Stripe) remain unconfigured and payment UI buttons remain disabled until bank reconciliation and 12A/80G/FCRA legal verification conclude.

## 3. Backup & Recovery Guidance
- **Source Media Archive:** Keep offline encrypted backups of original supplied photography outside public cloud buckets with access restricted to safeguarding leads.
- **Database Backups:** Enable Supabase automated daily PITR backups before onboarding live enquiries or volunteer records.
- **Code & Configuration:** Preserve `.env.local` secrets exclusively in encrypted host vault; never commit credentials or `.private/` to Git.
